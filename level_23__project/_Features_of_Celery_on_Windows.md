## ❗ Особенности запуска Celery в операционной системе Windows 

Если вы запускаете проект на Windows, команда:

```bash
celery -A celery_app worker --loglevel=INFO -E
```

может не работать и выдавать ошибки, даже если вы всё сделали правильно.

Это связано с особенностями работы **Celery** на Windows.

### В чём причина?

По умолчанию Celery использует пул процессов `prefork`, который основан на механизме `fork()`.

Механизм `fork()`:

* есть в Linux и macOS
* ⚠️ отсутствует в Windows

Поэтому стандартный запуск worker'а может завершаться ошибкой.

---

Поэтому, используйте один из следующих вариантов:

### Вариант 1 (рекомендуется)

```bash
celery -A celery_app worker --pool=solo -l info
```

* Один процесс
* Без параллелизма
* Самый стабильный вариант для Windows

---

### Вариант 2 (если нужна параллельность)

```bash
celery -A celery_app worker --pool=threads --concurrency=4 -l info
```

* Используются потоки вместо процессов
* Работает на Windows
* Подходит для I/O-задач (запросы к БД, HTTP и т.д.)

---

## Рекомендация

Для production-окружения и полноценной работы Celery рекомендуется использовать:

* Linux
* Docker
* или WSL2

Celery изначально проектировался под Unix-системы, поэтому на Windows возможны ограничения.
