## Специфика обработки ошибок в async-приложениях

В приложениях, использующих `asyncio`, обработка ошибок имеет несколько особенностей,  
которых нет в обычном ("синхронном") коде.

Основная причина заключается в том, что операции выполняются **внутри event loop**,  
а выполнение задач может происходить одновременно.

Из-за этого исключения могут возникать в разных контекстах:

* внутри обработчика запроса;
* внутри фоновой задачи;
* внутри параллельно выполняющихся задач;
* внутри сторонних библиотек.

Если такие ошибки не обработать корректно, они могут:

* остаться незамеченными;
* прервать выполнение задачи;
* привести к некорректному состоянию приложения.

Кроме того, в `asyncio` действует тот же принцип, что и в обычном Python-коде:  
необработанные исключения "всплывают" вверх по стеку вызовов.

Если на пути не окажется обработчика (try/except, middleware или exception handler),  
исключение может дойти до уровня обработчика запроса или даже до event loop.

В зависимости от контекста это может привести к разным последствиям:
* завершению конкретной задачи;
* разрыву обработки HTTP-запроса;
* записи ошибки в лог event loop;
* в некоторых случаях — остановке сервера.

Поэтому в async-приложениях важно понимать, **где именно возникает исключение и кто его должен обработать**.

---

### 1. Ошибки внутри async-функций

Наиболее простой случай — ошибка внутри обычной `async`-функции.

Она обрабатывается так же, как и в обычном коде.

```python
async def calculate(value: int):

    try:
        result = 100 / value
        return result

    except ZeroDivisionError:
        return "Invalid value"
```

Если функция вызывается через `await`, исключение будет передано вызывающему коду.

```python
result = await calculate(0)
```

Таким образом, правило остаётся тем же:
**исключение поднимается вверх по стеку вызовов**, пока его кто-то не перехватит.

---

### 2. Ошибки в параллельно выполняющихся задачах

В async-коде задачи часто запускаются параллельно с помощью `asyncio.create_task()`.

```python
import asyncio

async def background_job():
    raise RuntimeError("Something went wrong")

async def main():
    asyncio.create_task(background_job())
```

Проблема здесь в том, что вызывающий код **не ожидает завершения задачи**.

В результате исключение может привести к предупреждению:

```
Task exception was never retrieved
```

Это означает, что ошибка произошла, но её **никто не обработал**.

---

### 3. Решение: ожидание задачи

Самый простой способ решить проблему — **ожидать выполнение задачи**.

```python
task = asyncio.create_task(background_job())

try:
    await task
except Exception as error:
    print("Task failed:", error)
```

Теперь исключение будет корректно обработано.

---

### 4. Использование asyncio.gather

Когда запускается несколько задач одновременно, удобно использовать `asyncio.gather`.

```python
results = await asyncio.gather(
    task1(),
    task2(),
    task3()
)
```

По умолчанию:

* если одна задача завершится с ошибкой,
* `gather` выбросит исключение.

Поэтому важно правильно изменить это поведение с помощью параметра `return_exceptions=True`:

```python
results = await asyncio.gather(
    task1(),
    task2(),
    return_exceptions=True
)
```

Теперь исключения будут возвращены как элементы списка результатов.

Это позволяет обработать ошибки отдельно.

---

### 5. Ошибки в фоновых задачах FastAPI

FastAPI позволяет запускать фоновые задачи, например через `BackgroundTasks`.

```python
from fastapi import BackgroundTasks

async def send_email():
    raise RuntimeError("Mail server error")
```

Если внутри такой задачи возникает ошибка, она **не влияет на HTTP-ответ**,  
потому что задача выполняется после отправки ответа клиенту.

Поэтому важно **логировать ошибки внутри самой задачи**.

```python
import logging

logger = logging.getLogger(__name__)

async def send_email():
    try:
        # отправка письма
        pass

    except Exception:
        logger.exception("Email sending failed")
```

---

### 6. Ошибки отмены задач

В `asyncio` существует специальное исключение — `CancelledError`.

Оно возникает, когда задача отменяется.

```python
import asyncio

async def job():

    try:
        await asyncio.sleep(10)

    except asyncio.CancelledError:
        print("Task cancelled")
        raise
```

Важно **не подавлять это исключение**, иначе система управления задачами может работать некорректно.

Правильный подход — перехватить исключение, выполнить необходимую очистку и снова его выбросить.

---

### 7. Общие рекомендации

При работе с async-кодом полезно соблюдать несколько правил.

**1. Всегда ожидайте задачи**

Если используется `create_task`, важно:

* либо `await` задачу
* либо обрабатывать её результат.

---

**2. Логируйте ошибки в фоновых задачах**

Фоновые задачи могут завершиться с ошибкой, но пользователь об этом не узнает.
Поэтому логирование особенно важно.

---

**3. Используйте exception handlers**

Ошибки внутри обработчиков запросов лучше обрабатывать через:

* `HTTPException`
* глобальные exception handlers.

---

**4. Используйте middleware как последний уровень защиты**

Middleware может перехватывать неожиданные ошибки и логировать их.

---

### Итог

В приложениях, использующих `asyncio`, ошибки могут возникать в разных контекстах выполнения:

* внутри `async`-функций;
* внутри параллельно выполняющихся задач;
* внутри фоновых задач;
* при отмене задач.

Поэтому система обработки ошибок обычно включает несколько уровней:

```text
async function
      │
      ▼
try/except
      │
      ▼
Exception handlers
      │
      ▼
Middleware
      │
      ▼
Logging
```

Такой подход позволяет:

* корректно обрабатывать известные ошибки;
* предотвращать падение приложения;
* сохранять информацию о сбоях для дальнейшего анализа.
