## Ошибки отмены задач

В `asyncio` существует специальное исключение — `CancelledError`.
Оно используется механизмом `asyncio` для **корректной остановки выполняющихся задач**.

Когда задача отменяется, внутри неё генерируется исключение `CancelledError`.

---

### 1. Как происходит отмена задачи

Предположим, задача запущена через `create_task`.

```python
import asyncio

async def job():
    await asyncio.sleep(10)
    print("Finished")

async def main():
    task = asyncio.create_task(job())

    await asyncio.sleep(1)
    task.cancel()

    await task

asyncio.run(main())
```

Что происходит:

1. создаётся задача `job`
2. она начинает выполняться
3. через секунду вызывается `task.cancel()`

В этот момент `asyncio` **не останавливает функцию мгновенно**.
Вместо этого внутри задачи генерируется исключение:

```
asyncio.CancelledError
```

Это исключение возникает в той точке, где задача **ожидает результат другой операции (`await`)**.

---

### 2. Где возникает CancelledError

Например здесь:

```python
await asyncio.sleep(10)
```

Когда вызывается `task.cancel()`, выполнение `sleep()` прерывается и выбрасывается:

```
CancelledError
```

---

### 3. Что происходит без обработки

Если исключение не перехватывается, оно просто **поднимается вверх и завершает задачу**.

Это нормальное поведение.

Иногда в консоли можно увидеть сообщение вроде:

```
Task was cancelled
```

---

### 4. Почему иногда нужно перехватывать CancelledError

Иногда задача выполняет действия, требующие **завершения или очистки ресурсов**:

* закрытие соединения с базой данных
* освобождение блокировки
* запись состояния в файл
* завершение сетевого соединения

В таких случаях нужно перехватить исключение, выполнить очистку и **позволить задаче завершиться корректно**.

Пример:

```python
import asyncio

async def job():

    try:
        await asyncio.sleep(10)

    except asyncio.CancelledError:
        print("Cleaning up resources")
        raise
```

Здесь происходит:

1. задача получает сигнал отмены
2. возникает `CancelledError`
3. код выполняет очистку
4. исключение **снова выбрасывается**

---

### 5. Почему нельзя просто "проглотить" исключение

Неправильный пример:

```python
async def job():

    try:
        await asyncio.sleep(10)

    except asyncio.CancelledError:
        print("Task cancelled")
```

Здесь исключение **подавляется**.

С точки зрения `asyncio` это означает:

> задача НЕ была отменена

В результате:

* механизм управления задачами может работать некорректно
* вызывающий код может ожидать отмены, но её не произойдёт
* задача может продолжить выполнение

---

### 6. Правильный паттерн

Правильный подход выглядит так:

```python
async def job():

    try:
        await asyncio.sleep(10)

    except asyncio.CancelledError:
        print("Cleaning up resources")
        raise
```

Шаблон:

```
перехватить → выполнить очистку → снова выбросить
```

---

### 7. Где это реально используется

Отмена задач происходит довольно часто:

#### при остановке сервера

Когда сервер FastAPI завершает работу, активные задачи отменяются.

---

#### при таймаутах

Например:

```python
await asyncio.wait_for(job(), timeout=5)
```

Если время вышло — задача отменяется.

---

#### при отмене клиентского запроса

Если клиент закрывает HTTP-соединение, обработка запроса может быть отменена.

---

### 8. Ключевая идея

`CancelledError` — это **не обычная ошибка**, а **сигнал системы управления задачами**.

Поэтому правило исключение `CancelledError`:
* можно и нужно перехватывать
* но нельзя подавлять

---

### Итог

* При отмене задачи `asyncio` генерирует исключение `CancelledError`.
* Его используют для корректного завершения задачи.
* Если необходимо выполнить дополнительную логику (например, освободить ресурсы),
  * можно перехватить это исключение, 
  * но после выполнения необходимых действий его следует **снова выбросить**, 
    * чтобы система управления задачами корректно завершила задачу.
